1. Vision & Problem Statement
Existing systems (NTES, RTIS, ixigo/RailYatri Smart ETA) answer one question ΓÇö when will this train arrive? ΓÇö at ~90ΓÇô95% station-level accuracy using GPS + schedule + ML.
Synapse keeps that baseline and adds what none of them expose: why the number is what it is, how confident the system is, and what could change it ΓÇö surfaced differently to each stakeholder (passenger, station staff, control room, crew, feeder operator), each getting only what they need to act.
One-line identity: Synapse doesnΓÇÖt just predict arrival ΓÇö it explains the journeyΓÇÖs uncertainty and tells each stakeholder what to do about it.

10. ML / Statistical Architecture
ETA point forecast: gradient-boosted regression or lightweight sequence model per section-hop ΓÇö simplest model that hits the accuracy target wins; not forced-ML.
Uncertainty: quantile regression or historical-residual-based intervals per section/time-band ΓÇö a methodology, not a flat percentage.
Network interaction: graph-based model, used only for interaction/propagation layer, not the base point forecast.
Attribution: feature-contribution decomposition from the same model already producing the forecast ΓÇö not a bolted-on second model.
Deliberately not ML: fallback/degraded mode (rule-based), conflict forecaster (deterministic rules), sync-window sizing (deterministic from uncertainty band).

11. API Layer (condensed)
All read endpoints are cached and served from the shared feature layer ΓÇö no per-request recomputation. Recomputation is event-triggered (new GPS ping, new event notice), not fixed-interval polling, so cost scales with real state change, not train-count ├ù time.

12. Non-Functional Requirements
Scale: thousands of trains concurrently ΓÇö shared feature cache, incremental per-section computation (R16).
Reliability: every interface surfaces stale-data flags; no silent degradation anywhere (R13/D13).
Continuous learning: feedback loop closes actual-vs-predicted back into the Historical Behaviour Engine (R17).
Configurability: per-zone/division config layer for operational diversity (R15).

15. Risks, Assumptions & Open Questions
Prior art: point-ETA-via-ML is already deployed at scale in India (ixigo/RailYatri, NTES/RTIS) ΓÇö do not pitch the baseline forecasting engine itself as novel; differentiation is in the explanation/uncertainty/network layer.
Graph-based delay-propagation modelling is an active published research area (Dutch/Chinese rail networks) ΓÇö SynapseΓÇÖs application to the Indian network with real-time control-room decision support has no known deployed equivalent, but this should be validated, not overclaimed.
Calibrated, methodology-grounded uncertainty was not found exposed in any publicly searched Indian passenger-facing system ΓÇö treat as ΓÇ£not found in what we checked,ΓÇ¥ not a novelty claim.
Second-order features (┬º7.3) require further validation before committing engineering time or presenting them as fully original to judges.
R21 (crew scheduling) is data-blocked unless a duty-roster feed is confirmed accessible ΓÇö do not fabricate this data source.
